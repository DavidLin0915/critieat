# CRITIEAT 結構化菜單 設計

日期：2026-10-15　狀態：燈箱 mockup 已實作並經使用者確認（`proto/v1`），上傳／辨識流程 mockup 已實作待審核；正式功能排在第二階段（有後端與 DB 之後）

## 目的

Google Maps 上的菜單照片和自己拍的照片常常歪斜、反光、字太小，不好讀。
改成把菜單整理成**結構化表格**存進 DB，用燈箱顯示；原始照片保留，隨時可以切換對照。

整理菜單最花工夫的是輸入，所以用 AI 看圖產生草稿，人只負責校對。

## 決定事項（2026-10-15 與使用者確認）

| 項目 | 決定 |
|---|---|
| 菜單形式 | 結構化表格（分類、品名、價格、備註）＋保留原始照片。**取代** 2026-10-08 的「菜單用照片，不做結構化品項」 |
| 顯示 | 燈箱，兩個分頁：「菜單表格」「原始照片」；表格上方有分類快捷鈕 |
| 入口 | 美食地圖店家詳情、開團單右欄店家資訊，各有「📋 看菜單」 |
| 更新提醒 | 顯示「最後更新 日期 · 由 某某 整理」；超過 60 天變黃色提醒「價格可能有變」 |
| 建立方式 | 上傳照片或貼圖片網址 → 後端呼叫 Claude 看圖 → 回傳草稿 → **人工確認／修正** → 存進 DB |
| 人工確認 | 必要步驟，AI 結果不直接寫進 DB |
| 誰能建立或更新 | 任何人（跟店家編輯一樣，不做權限） |
| 階段 | 第二階段；第一階段沒有 DB，維持原狀 |

## 資料

結構對應原型假資料 `proto/v1/js/menu-demo.js`。每家店只有一份「目前的菜單」，重新上傳並確認後整份取代。

> 2026-10-16 修改：整份取代時，**品名＋備註相同的品項沿用舊的 `menu_items.id`**（讓品項評分與點餐連結不斷掉），對不上的舊品項下架。見 `2026-10-16-critieat-item-rating-design.md`。

### menus

| 欄位 | 說明 |
|---|---|
| `id` | 菜單 ID |
| `store_id` | 店家 ID（一家店一筆） |
| `updated_at` | 最後確認儲存的時間 |
| `updated_by` | 最後確認儲存的人（成員名字） |

### menu_photos

| 欄位 | 說明 |
|---|---|
| `id` | 照片 ID |
| `menu_id` | 所屬菜單 |
| `path` | 存放位置（後端儲存空間） |
| `source_url` | 從網址抓來的話，記下原網址；上傳的為空 |
| `sort` | 多頁菜單的頁序 |

### menu_items

| 欄位 | 說明 |
|---|---|
| `id` | 品項 ID |
| `menu_id` | 所屬菜單 |
| `category` | 分類名稱（例如「飯類」「湯品」）；顯示順序依 `sort` 第一次出現的位置 |
| `name` | 品名 |
| `price` | 價格，可有小數（例如鍋貼每顆 6.5）；不確定可為空 |
| `note` | 備註，選填（「小」「大」「每顆，10 顆起」「冰 / 熱」） |
| `sort` | 顯示順序 |

同一品項不同份量（魯肉飯小／大）存成兩列，用 `note` 區分，不另做規格表。

## 建立／更新流程

```
① 店家詳情 → 「上傳菜單」：選照片（可多張）或貼圖片網址
      ↓
② 後端存照片 → 呼叫 Claude 看圖 → 回傳 JSON 草稿
      ↓
③ 前端顯示可編輯的草稿表格（可改、可刪、可加列、可改分類）
   AI 沒把握的列標黃色，價格讀不出來的留空
      ↓
④ 「確認儲存」→ 寫進 menus／menu_photos／menu_items，取代舊菜單
      ↓
⑤ 燈箱顯示新菜單，更新日期與整理人換成這次的
```

在③按「取消」就不改動舊菜單，這次上傳的照片也不保留。

### AI 辨識

- 由後端（Laravel `critieat_api`）呼叫；API key 只放在後端，前端拿不到。
- 一次送出同一份菜單的所有照片，要求回傳固定格式：`[{ category, name, price, note, uncertain }]`。
- 提示詞重點：只抄照片上看得到的內容，**不要猜價格**；看不清楚的價格留空並設 `uncertain: true`。
- 模型型號在實作時再選；費用預估每份菜單台幣幾毛到一塊。

### 圖片網址

- 只接受直接指向圖片檔的網址；後端抓取後檢查是不是圖片、大小上限 10MB。
- Google Maps 分享連結（`maps.app.goo.gl/…`）不是圖片，會提示「請改用截圖上傳」。要直接從 Maps 抓照片得另外開 Places API，不在這次範圍。

### 錯誤處理

| 狀況 | 處理 |
|---|---|
| AI 呼叫失敗或逾時 | 提示「辨識失敗」，照片保留在草稿畫面，可以重試或手動輸入 |
| 圖片不是菜單／辨識結果是空的 | 提示「沒有辨識到菜單品項」，可以手動輸入 |
| 網址抓不到或不是圖片 | 提示原因，請改用上傳 |
| 檔案太大或格式不對 | 上傳前在前端就擋下 |

## 與開團單的關係

開團單的點餐維持自由輸入，不受影響。「從菜單選品項、自動帶入價格」列為之後再決定的項目（見下方「待決定」）；若要做，點餐列多一個可選的 `menu_item_id`，沒選就跟現在一樣。
