# CRITIEAT 需求與第一階段設計

- 日期：2026-10-08
- 狀態：已核准（2026-10-08）
- 範圍：整體需求與分階段規劃（第一～六階段）＋ 第一階段「午餐美食地圖」詳細設計

---

## 1. 背景與目標

辦公室午餐團（約 10 人）每天中午都要決定吃什麼，目前要在 Google Maps 上一間一間找，而地圖上混雜各行各業的圖標，查營業時間、電話、外送連結都很麻煩。

**目標**：快到中午時，大家打開一個網頁就能快速瀏覽「只有我們會去的店」，並一眼看出哪些店在午餐時段有開。

**成功標準**：午餐團在決定午餐時，改用 CRITIEAT 取代 Google Maps 瀏覽店家。

**限制與前提**

- 使用者：辦公室同事，最多約 10 人，彼此信任
- 開發：一人構想、設計、開發
- 店家資料由內部同事自行維護
- 團隊已有自用的 Google Maps API Key
- 午餐一律是外帶或外送回辦公室（不需要「出去吃」的情境）
- 午餐節奏：約 12:30 開始想 → 13:00～13:30 訂餐 → 13:45～14:00 拿到餐點

## 2. 技術路線

沿用團隊既有專案（critical、drink、2511flower）的技術與流程：

| 模組 | 技術 | 何時建立 |
|---|---|---|
| `proto/v1/` | 靜態 HTML 原型（假資料） | 第一階段 |
| `critieat_web/` | Nuxt 3（Vue 3 / TypeScript），獨立 git repo | 第一階段 |
| `critieat_api/` | Laravel，獨立 git repo | 第二階段 |

- 流程：Contract-First。靜態原型 → `contracts/`（含驗收標準）→ 人工審核 → 依原型還原成 Nuxt 頁面
- 寫法：對齊 critical_web 的慣例（composables / components / pages 拆法）
- 驗證：不引入測試框架，以 `npm run build` 通過，加上 `npm run dev` 實際比對原型為準
- 架構上最接近 critical：前台＋API，**不做獨立後台**（店家資料改在前台直接編輯，第二階段起）

## 3. 分階段規劃

| 階段 | 名稱 | 內容 | 資料／架構 |
|---|---|---|---|
| 一 | 午餐美食地圖 | 店家資料欄位設計、製作店家 CSV、Google 地圖呈現（隱藏其他圖標、分類標籤）、營業狀態 | Google Sheet 發布 CSV，前端直接讀取；無 DB |
| 二 | 開團單 | 後端建置、店家資料從 Sheet 搬進 DB、前台新增／編輯店家（Google Places 自動帶入）、菜單上傳與 AI 辨識（見 `2026-10-15-critieat-menu-design.md`）、身份認領、提議、開單、收單、午餐單細節＆紀錄 | 建立 `critieat_api`（Laravel）＋ DB |
| 三 | 公車地圖 | 蒐集附近公車站點與路線、公車地圖頁面 | 需串接公車資料（如 TDX），獨立子專案 |
| 四 | 午餐轉盤及回饋 | 午餐轉盤、店家星等與短評 | 轉盤原型已做（2026-10-15，見 `2026-10-15-critieat-lunch-picker-design.md`）；評分設計見 `2026-10-15-critieat-store-rating-design.md` |
| 五 | 進階篩選 | 分類、區域、星期、評分等篩選；點到點公車篩選 | |
| 六 | 飲料地圖 | 待美食、公車階段完成後再規劃 | 預計共用店家資料，以分類區分 |

每個階段各自走一次「原型 → 審核 → 實作」。

### 3.1 後續階段已確定的方向（詳細設計留待該階段）

- **身份認領**：訪客式，從成員名單選自己的名字（沒有就新增），存在瀏覽器，可切換；不用帳號密碼
- **午餐卡**：只有一種卡片，狀態為「提議中 → 點餐中 → 已收單」
  - 提議：大家按 +1；沒人附和的提議當天結束自動收起
  - 開單：提議原地轉成午餐單，+1 的人自動列入；也可以跳過提議直接開單
  - 點餐：每人自由填寫餐點、價格、備註（不維護結構化菜單）
  - 收單：截止時間到或手動收單，產生彙總清單（份數、合計）
  - 同一天可以有多張卡片
- **店家編輯**：任何人可在前台新增／編輯；顯示「最後由誰更新」；刪除改為隱藏
- **菜單**：~~用照片，不做結構化品項~~ → 2026-10-15 改為結構化表格＋保留原始照片，AI 辨識產生草稿，見 `2026-10-15-critieat-menu-design.md`
- **飲料**：與餐廳共用店家資料與開單機制，飲料卡多甜度／冰塊快選

## 4. 第一階段詳細設計：午餐美食地圖

### 4.1 範圍

**包含**：店家清單、乾淨的 Google 地圖、店家詳情、營業狀態（含「隱藏沒開的店」開關）、分類標籤、依距離排序

**不包含**：篩選、搜尋、菜單、評分、登入、前台編輯店家

### 4.2 畫面結構與使用流程

單一主頁面。

```
桌機
┌──────────────────────────────────────────────────────┐
│ CRITIEAT                        [☐ 隱藏沒開的店]       │
├────────────────────┬─────────────────────────────────┤
│ 店家清單             │                                 │
│ ┌────────────────┐ │                                 │
│ │🍜 XX 拉麵  有開   │ │         Google 地圖              │
│ │   麵類 · 350m   │ │    （只有我們的店＋公司位置）       │
│ └────────────────┘ │                                 │
│ ┌────────────────┐ │      ● 午餐有開（彩色）            │
│ │🍱 OO 便當  沒開   │ │      ○ 午餐沒開（灰色）            │
│ └────────────────┘ │      ★ 公司                      │
└────────────────────┴─────────────────────────────────┘

手機：地圖在上、清單在下（或以分頁切換）
```

- **地圖**：Google Maps JavaScript API，以自訂樣式隱藏所有其他商家圖標（POI），只畫我們的店與公司位置
- **店家詳情**：點清單或地圖標記時開啟（桌機用側欄、手機用底部抽屜），內容：
  - 店名、分類標籤、營業狀態、今天的營業時間、一週營業時間表
  - 地址、電話（手機可直接撥打）
  - 按鈕：Google Maps 導航、foodpanda、Uber Eats、你訂（有填才顯示）
  - 備註
- **清單與地圖連動**：點清單 → 地圖移動到該店並開啟標記；點地圖標記 → 清單捲動到該店並開啟詳情
- **排序**：依營業狀態（午餐有開、提早打烊、不確定在前，午餐沒開在後），再依距離公司由近到遠
- **距離**：以公司座標計算直線距離

### 4.2.1 視覺風格

採用 **A. Critical 官網風**，與公司官網同一家族（樣本：`docs/design/style-a-critical.html`）：

- 白底、深灰字（`#111827`），毛玻璃卡片、細灰框（`#e5e7eb`）
- 點綴色：霓虹青 `#00f0ff`、紫 `#bc13fe`；背景有模糊漸層色塊
- 字體：Inter ＋ Noto Sans TC；編號、標籤用 JetBrains Mono
- 營業狀態色：午餐有開＝青、提早打烊＝紫、不確定＝黃、午餐沒開＝灰
- 版面：桌機 16:9，頂部導覽列，左清單／中地圖／右詳情三欄

備選樣本：**C. 溫暖食物感**（`docs/design/style-c-warm.html`）保留參考，不採用。

### 4.3 資料欄位（Google Sheet）

#### 「店家」工作表

一列一家店。表頭用中文；程式內維護一份「中文表頭 → 英文欄位名」對照表，與未來 DB 欄位對應。

| 欄位 | 英文欄位名 | 必填 | 格式／範例 | 說明 |
|---|---|---|---|---|
| ID | `id` | ✅ | `R001` | 固定不變，未來評分、開團單以此關聯，填了不改 |
| 店名 | `name` | ✅ | XX 拉麵 | |
| 分類 | `category` | ✅ | 下拉：飯、麵、便當、小吃、異國、輕食、其他 | 以資料驗證做成下拉 |
| 區域 | `area` | | 公司旁、XX 路 | 第五階段篩選用，可先空白 |
| 地址 | `address` | ✅ | 台北市… | |
| 緯度 | `lat` | 自動 | `25.0330` | 由 Apps Script 產生，不手填 |
| 經度 | `lng` | 自動 | `121.5654` | 由 Apps Script 產生，不手填 |
| 電話 | `phone` | | 02-1234-5678 | |
| 週一～週日 | `hours_mon`～`hours_sun` | | `11:00-14:00, 17:00-20:30`／`公休`／空白 | 7 欄，格式見 4.5 |
| Google Maps 連結 | `google_maps_url` | | 網址 | |
| foodpanda | `foodpanda_url` | | 網址 | |
| Uber Eats | `ubereats_url` | | 網址 | |
| 你訂 | `nidin_url` | | 網址 | |
| 備註 | `note` | | 要提早打電話訂 | |
| 顯示 | `visible` | ✅ | 下拉：是／否 | 「否」＝隱藏（軟刪除） |

#### 「設定」工作表

鍵值形式（A 欄名稱、B 欄值）。

| 名稱 | 範例值 | 用途 | 缺值時預設 |
|---|---|---|---|
| 公司名稱 | CRITICAL | 地圖標記 | `公司` |
| 公司緯度 | `25.xxxx` | 地圖中心、距離計算 | 無（缺值時地圖以店家範圍置中，不顯示距離） |
| 公司經度 | `121.xxxx` | 同上 | 同上 |
| 訂餐時段 | `13:00-13:30` | 營業狀態判斷 | `13:00-13:30` |
| 取餐時間 | `14:00` | 提早打烊判斷 | `14:00` |

### 4.4 資料流程

```
Google Sheet
  同事填寫／修改店家
    → Apps Script 自動補上緯度、經度（只在資料變動時執行）
    → 「發布到網路」：店家 CSV 網址、設定 CSV 網址
        │ 網頁開啟時 fetch
        ▼
critieat_web（Nuxt 3）
  composable：抓 CSV → 解析 → 中文表頭轉英文欄位名
            → 過濾 visible = 否 → 判斷營業狀態 → 計算距離 → 排序
    → 清單元件 ⇄ 地圖元件（Google Maps JS API）⇄ 詳情元件
```

- **座標**：試算表內的 Apps Script（installable onEdit 觸發），在地址新增或變更時用 Apps Script 內建的 Maps 地址轉座標服務填入 `lat`／`lng`；另提供選單「重新計算座標」作為手動補救。需要一位同事以 Google 帳號授權一次
- **Google Maps Key**：只用於顯示地圖；在 Google Cloud 設定 HTTP 參照網址限制
- **更新頻率**：每次開啟或重新整理網頁都重新抓取；Google 發布的 CSV 會延遲數分鐘才反映最新內容，可以接受
- **原型階段**：`proto/v1/` 使用寫死的假資料，不接 Google Sheet

### 4.5 營業狀態判斷

以**台灣時間（Asia/Taipei）的今天**判斷，對照「設定」中的訂餐時段與取餐時間。與「現在這一刻有沒有開」無關，因此 10 點打開網頁也能看到中午的狀態。

| 狀態 | 條件 | 顯示 | 「隱藏沒開的店」勾選時 |
|---|---|---|---|
| 🟢 午餐有開 | 某個營業時段與訂餐時段重疊，且在取餐時間（含）之後才打烊 | 彩色 | 顯示 |
| 🟠 提早打烊 | 某個營業時段與訂餐時段重疊，但在取餐時間前打烊 | 彩色＋提醒「HH:MM 打烊，要早點訂」 | 顯示 |
| ⚪ 午餐沒開 | 今天為 `公休`，或沒有任何營業時段與訂餐時段重疊 | 灰色 | 隱藏 |
| 🟡 不確定 | 今天欄位空白，或格式無法解析 | 彩色＋「?」標記 | 顯示 |

以預設值（訂餐 13:00-13:30、取餐 14:00）為例：

| 今天營業時間 | 狀態 |
|---|---|
| `11:00-14:30` | 🟢 午餐有開 |
| `11:00-13:30` | 🟠 提早打烊（13:30 打烊） |
| `11:00-13:00` | ⚪ 午餐沒開 |
| `17:00-21:00` | ⚪ 午餐沒開 |
| `公休` | ⚪ 午餐沒開 |
| 空白 | 🟡 不確定 |

**營業時間格式**

- 單一時段：`11:00-14:00`
- 多個時段以逗號分隔：`11:00-14:00, 17:00-20:30`（逗號前後空白可有可無）
- 整天公休：`公休`
- 跨午夜（結束早於開始，例如 `18:00-02:00`）視為延續到隔天，可解析但不影響午餐判斷
- 試算表的營業時間欄位設資料驗證，格式不符時警告

**不處理**：國定假日、臨時店休（寫在備註或暫時改為 `公休`）、「營業中／快打烊」等即時狀態。

### 4.6 錯誤處理

原則：任何一部分失敗，其他部分照常可用。

| 狀況 | 處理 |
|---|---|
| 抓不到 CSV | 顯示上次成功的資料（存於瀏覽器），提示「資料可能不是最新的」並提供「重新載入」；從未成功過則顯示錯誤訊息與重試按鈕 |
| Google 地圖載入失敗 | 地圖區顯示「地圖暫時無法使用」，清單、詳情照常運作 |
| 店家沒有座標 | 只出現在清單並標示「地圖位置未設定」，不畫在地圖上 |
| 缺少必填欄位（ID、店名） | 略過該列，console 警告 |
| 營業時間無法解析 | 歸為 🟡 不確定 |
| 設定工作表缺值 | 使用 4.3 的預設值 |

### 4.8 第一階段交付順序

1. 靜態原型 `proto/v1/`（假資料）→ 審核

5. 部署上線
