# CRITIEAT 菜單 AI 辨識（Gemini） 設計

日期：2026-10-22　狀態：設計中，待使用者審核

## 目的

正式版上傳菜單照片後，還要自己一筆一筆輸入品項，太麻煩（使用者 2026-10-22）。
這次把原型就做好的「上傳 → 辨識中 → 確認草稿 → 儲存」流程接上真的 AI：AI 看照片產生草稿，人只負責校對。

畫面與流程照已核准的原型（`docs/specs/2026-10-15-critieat-menu-design.md`），不重新設計。原型的假辨識在 `proto/v1/js/menu-draft.js` 的 `fakeRecognize`、`proto/v1/js/menu-lightbox.js` 的 `showLoading`。
第一階段 spec（`docs/specs/2026-10-20-critieat-supabase-phase1-design.md`）把 AI 辨識列為不做；這次補上。原菜單 spec 寫的「由 Laravel 呼叫」改成 Supabase Edge Function，因為專案已經改用 Supabase。

## 決定事項

| 項目 | 決定 | 來源 |
|---|---|---|
| AI 服務 | Google Gemini API **免費方案**（Google AI Studio 的 key） | 使用者 2026-10-22 |
| 照片來源 | 自己拍的紙本菜單、Google Maps 截圖都會有 | 使用者 2026-10-22 |
| AI 結果 | 辨識完**帶進可編輯的草稿**，人改完按儲存才寫入；不會辨識完直接換掉菜單 | 使用者 2026-10-22 |
| 已有菜單的店 | **舊品項保留，新辨識到的加進去**（不是只留這次辨識到的） | 使用者 2026-10-22（選項 B） |
| 照片 | 重新上傳時，新照片**取代**舊照片（同現行行為） | 使用者 2026-10-22 |
| API key | 只存在 Supabase secrets，前端與 repo 都看不到；使用者自己設定，不貼進對話 | 使用者 2026-10-22 |

## Claude 的決定（請在審 spec 時確認）

- **後端＝一支 Supabase Edge Function**（例如 `menu-recognize`，原始碼放 `supabase/functions/menu-recognize/`）。前端把照片送給它，它呼叫 Gemini、回傳草稿列。Gemini key 從環境變數 `GEMINI_API_KEY` 讀。
- **要通關碼才能用**：函式先用請求帶的 `x-team-code` 呼叫資料庫的 `check_team_code`，不對就回 403。前端沿用 `CE.supa` 的通關碼流程（沒有碼或碼錯時跳出同一個輸入框，輸入後重送）。理由：不擋的話任何人都能拿這支函式用掉團隊的免費額度。
- **模型**：用免費方案有提供、支援看圖的 Gemini Flash 系列，型號由 builder 實作時查 ai.google.dev 決定，並且可以用環境變數（例如 `GEMINI_MODEL`）換掉，不用改程式。
- **換供應商的接縫**：函式裡「呼叫哪家 AI」集中在一個小函式，輸入照片、輸出草稿列。以後要換成 Claude 只改這段＋換 key。這次**不做** Claude 版本。
- **回傳格式**：`[{ category, name, price, note, uncertain }]`，跟現有草稿列一樣（`price` 是數字或 null）。要求 Gemini 用 JSON schema 結構化輸出，函式再檢查一次格式，不合格的列丟掉。
- **提示詞重點**（沿用原菜單 spec）：
  - 只抄照片上看得到的內容，**不要猜價格**；看不清楚的價格留空並設 `uncertain: true`，品名看不清楚也設 `uncertain`。
  - 品名照菜單原文（繁體中文），不翻譯、不美化。
  - 同一品項有大小份或不同口味不同價時，拆成多列，差別寫在 `note`（例如「大」「小」）。這樣跟品項 ID 的「品名＋備註」比對規則一致。
  - 分類照菜單上的標題；沒有標題就留空（存檔時會歸到「其他」）。
  - 不是菜單的照片回傳空陣列。
- **照片怎麼送**：上傳的檔案沿用現有的 `shrink`（長邊 1200px）縮小後送出。貼網址的照片由函式去抓（檢查真的是圖片、10MB 上限），抓不到就在結果裡說哪一張失敗，其他張照樣辨識。**一次最多 6 張**，超過在前端就擋下。
- **合併規則（選項 B）**，寫成 `menu-draft.js` 裡的純函式（例如 `mergeRecognized(oldRows, aiRows)`），用 scratchpad 的 node 腳本驗：
  - 舊菜單的列全部保留，順序不變，原本不標黃。
  - AI 的列用「品名＋備註」（`menu-data.js` 的 `norm` 規則：全形轉半形、去前後空白、英文小寫）比對舊列：
    - 比對到、價格一樣，或 AI 價格是空的 → 不加，舊列不動。
    - 比對到、價格不同 → 舊列的價格改成 AI 讀到的，並且**標黃**，該列旁邊顯示「原價 $120」讓人對照；改過那列後提示跟著黃色一起消失。
    - 比對到、價格不同，但 AI 自己標 `uncertain` → **不改價格**，舊價格留著，只標黃。
    - 舊列原本沒價格、AI 讀到價格 → 填進去並標黃（沒有「原價」提示）。
    - 比對不到 → 加在最後面，保留 AI 的 `uncertain`。
  - 這次辨識裡重複出現的同一品項（例如兩張照片拍到同一頁）只留第一筆。
  - 舊列不會因為照片裡沒出現就被刪掉；停賣的品項由人自己按 × 刪。
  - 舊列保留，存檔時 `assignIds` 就會沿用原本的品項 ID，品項評分與點餐連結不會斷。
- **上傳畫面的按鈕**（正式版）：有照片時主按鈕是「開始辨識（n 張）」，旁邊加一個次要按鈕「不辨識，直接輸入」（走現在的 `startDraft`）。沒選照片時只有「直接輸入」。
- **辨識中畫面**：沿用原型的轉圈與「AI 正在讀菜單…」，拿掉「原型示意」那行；加一個「取消」回到上傳畫面，照片保留。逾時（例如 60 秒）視同失敗。
- **草稿畫面的提示文字**：辨識後用原型那句（「請對照照片檢查。AI 沒把握的列標成黃色…」）；選「直接輸入」時用現在正式版那句。
- **示範模式（`?demo=1`）不變**：照舊用 `fakeRecognize`，不呼叫函式。

## 範圍

### 要做

1. Edge Function：驗通關碼 → 整理照片 → 呼叫 Gemini → 檢查並回傳草稿列；錯誤回傳可分辨的代碼（見出錯處理）。
2. `menu-draft.js`：合併純函式。
3. `menu-lightbox.js`：正式版接上辨識流程、按鈕、取消、錯誤提示。
4. `CE.supa`（或新的小模組）：呼叫 Edge Function，帶通關碼、處理被擋重送。
5. `supabase/README.md`：新增一節，寫申請 key、設定 secret、部署函式的步驟。

### 不做

- 付費方案、綁信用卡
- Claude 或其他 AI 的實作（只留接縫）
- 抓 Google Maps 分享連結裡的照片（照舊提示「請截圖上傳」）、Places API
- 辨識結果自動存檔
- 記錄辨識次數、用量統計畫面
- 照片「加在舊照片後面」（使用者選取代）

### 反目標（做到了也算失敗）

- 產生任何費用
- Gemini key 出現在前端程式、網路請求的回應、repo 或對話裡
- 沒有通關碼也能呼叫辨識（含直接打函式網址）
- AI 的結果沒經過人按「確認儲存」就寫進資料庫
- 重新辨識後舊品項的 ID 變了，品項評分或點餐連結斷掉
- 辨識失敗時使用者選的照片不見
- `?demo=1` 壞掉或開始呼叫真的 AI

## 出錯處理

| 情況 | 處理 |
|---|---|
| 通關碼錯或沒有 | 跳出通關碼輸入框（同其他寫入）；取消就回上傳畫面，照片保留 |
| 免費額度用完（Gemini 回 429，可能是每分鐘或每天的上限） | 提示「免費辨識次數暫時用完了，可以過一陣子再試，或先直接輸入」，提供「直接輸入」 |
| 網路失敗、逾時、Gemini 其他錯誤 | 提示「辨識失敗」，可以重試或直接輸入，照片保留 |
| 辨識結果是空的（不是菜單或看不清楚） | 提示「沒有辨識到菜單品項」，可以直接輸入 |
| 有幾張網址照片抓不到 | 其他張照樣辨識，草稿上方提示哪幾張沒讀到 |
| 函式還沒部署或 key 沒設定 | 提示「辨識功能還沒設定好」，可以直接輸入（不要只顯示一般錯誤） |

失敗時停在一個錯誤畫面，提供「重試」與「直接輸入」；選直接輸入時草稿＝舊菜單或一列空白。
草稿畫面沒有「重新辨識」，辨識只從上傳畫面開始，所以合併的底永遠是已存的菜單。

## 驗收

- 正式版：選 2–3 張真實菜單照片（至少一張手機拍、一張 Google Maps 截圖）→ 開始辨識 → 草稿出現合理的品項，看不清楚的價格留空且標黃 → 修改 → 儲存 → 菜單燈箱顯示正確。
- 已有菜單的店：上傳只拍到部分品項的照片 → 舊品項都還在、新品項加在後面、改了價格的那列標黃；存檔後原有品項的評分還在。
- 合併規則的 node 腳本：一樣、價格不同、AI 沒價格、全形半形差異、重複列、備註不同的同名品項，都符合上面的規則。
- 不帶通關碼直接 `curl` 函式網址 → 403，而且沒有呼叫 Gemini。
- 瀏覽器開發者工具的網路紀錄裡看不到 Gemini key。
- 非菜單照片 → 提示沒有辨識到；斷網 → 提示失敗、照片還在。
- `?demo=1` 照舊是假辨識。
- 沿用團隊規則：不加測試框架；邏輯用 scratchpad 的一次性 node 腳本驗，UI 用瀏覽器驗。

## 需要使用者操作

- 到 Google AI Studio（aistudio.google.com）申請 API key，**不要**替那個 Google Cloud 專案綁帳單，免費方案才不會產生費用
- 把 key 設進 Supabase secrets（`GEMINI_API_KEY`），步驟寫在 `supabase/README.md`
- 部署 Edge Function（Claude 提供步驟）
- 知悉：Gemini 免費方案送出的內容可能被 Google 用來改進模型（菜單照片屬公開資訊）
