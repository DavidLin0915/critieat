# CRITIEAT 點餐連品項＋品項評分 設計

日期：2026-10-16　狀態：設計已與使用者確認，待審核 spec
mockup：`.superpowers/brainstorm/21186-1792119839/content/menu-rating.html`（燈箱，採 A 列內展開）、`lunch-items.html`（點餐自動完成＋收單後評分）

## 目的

店家評分（`2026-10-15-critieat-store-rating-design.md`）只看得出「這家好不好」。菜單結構化之後，再往下一層：

1. **點餐時決定點什麼**：看菜單、點餐時一眼看出哪幾道大家推、哪幾道踩雷。
2. **補足店家評分**：知道「招牌好吃但其他普通」這類細節（但不影響店家分數）。
3. **記錄自己吃過什麼**：自己點過、評過哪些，下次不要再點到地雷。

## 決定事項（2026-10-16 與使用者確認）

| 項目 | 決定 |
|---|---|
| 與店家評分的關係 | 各自獨立；品項分數不影響店家分數 |
| 評分規則 | 跟店家評分一樣：每人每品項一筆，可修改、可刪除；0.5～5 星、每 0.5 一級；短評選填最多 50 字 |
| 入口 | 菜單燈箱每列（列內展開）＋開團單已收單卡片中「自己點的」每列 |
| 點餐連品項 | 品名欄自動完成：打字下拉菜單品項，選了帶入品名／價格／備註並記下品項 ID；仍可自由輸入 |
| 菜單更新時的品項對應 | 「品名＋備註」相同就沿用舊品項 ID（漲價算同一道）；對不上的舊品項視為下架，評分保留但不在菜單顯示 |
| 舊點餐紀錄 | 沒有品項 ID 的點餐列，顯示時用「品名＋備註」對目前菜單；備註對不上但菜單上只有一道同名品項時也算對上（點餐備註常是「不要香菜」這類個人備註）；都對不上不顯示評分按鈕 |
| 身分 | 共用 `critieat.me` 與開團單成員名單 |
| 階段 | 原型（純前端、localStorage，用現有假菜單 R002／R005／R006）；後端在 DB 階段 |
| 實作順序 | 兩個計畫依序做：① 點餐連品項 → ② 品項評分 |

這份 spec 解決了 `2026-10-15-critieat-menu-design.md` 的「待決定：開團單是否要從菜單選品項」→ 要，用自動完成；並修改該 spec 的「重新上傳整份取代」→ 品項沿用 ID。

## 資料

### 菜單品項 ID

每個品項多一個 `id`（字串），同一家店內唯一。

- **示範菜單**（`menu-demo.js`）：固定 ID，格式 `<店家ID>-<兩位數序號>`，例如 `R002-01`。
- **比對鍵**：`品名 + '\n' + 備註`，兩者先做：去掉前後空白、全形英數與空白轉半形、英文轉小寫。中文不做同義轉換（「魯」≠「滷」）。
- **確認草稿儲存時**（`menu-draft` → 新菜單）：
  1. 依新菜單順序，每個品項找舊菜單中比對鍵相同、且還沒被用掉的品項 → 沿用它的 `id`。
  2. 找不到 → 給新 ID：`<店家ID>-<時間戳 base36><序號>`，保證不和舊 ID 重複。
  3. 舊菜單中沒被用到的品項 → 下架，不再出現在菜單上（不另外保存）。
  4. 同一份菜單有兩個比對鍵完全相同的品項 → 依順序各對各的舊品項，不會接到同一個 ID。
- **舊資料補 ID**：localStorage `critieat.menus.v1` 裡原型時期存的菜單沒有 `id` → 讀取時補上（規則同「新 ID」，但用固定種子 `<店家ID>-s<序號>`，讓每次讀到的 ID 一樣），並寫回。

### 開團單點餐列

點餐列（`card.items[]`）多一個選填欄位：

```
{ id, member, name, price, note, updatedAt, afterClose, menuItemId?: string }
```

- 用自動完成選了品項 → `menuItemId` = 品項 ID。
- 之後手動改**品名** → 清掉 `menuItemId`；只改價格或備註 → 保留。
- 沒有這個欄位（舊資料）或空字串 → 當作沒連。`isValidDb` 允許欄位不存在，存在時必須是字串。

### 品項評分

```
{ storeId: 'R002', itemId: 'R002-02', itemName: '魯肉飯', itemNote: '大',
  member: '小明', stars: 4.5, comment: '肥瘦剛好', updatedAt: '2026-10-16T05:30:00.000Z' }
```

- 唯一鍵 `(itemId, member)`；其餘規則與店家評分相同（`stars` 0.5 級距、`comment` 去空白後最多 50 字、`updatedAt` ISO）。
- `itemName`／`itemNote`：評分當時的品名與備註快照，讓品項下架後「我評過的」仍看得出是哪一道。每次儲存時更新成當下的值。
- 儲存：localStorage `critieat.itemRatings.v1` = `{ ratings: ItemRating[] }`。第一次載入寫入示範資料。
- 未來 DB：`item_ratings(item_id, member, stars DECIMAL(2,1), comment VARCHAR(50) NULL, item_name, item_note, updated_at)`，`UNIQUE(item_id, member)`；`menu_items.id` 在菜單更新時沿用；點餐列加 `menu_item_id NULL`。

### 平均與「大家推」

- 品項平均：同店家評分（四捨五入到 1 位、固定 1 位小數、一律顯示人數）。
- **大家推**：該店目前菜單上、平均 ≥ 4.0 的品項，依平均高到低、同分人數多的優先、再同分照菜單順序，取前 3。沒有符合的就不顯示這一排。

## 畫面

### ① 點餐自動完成（開團單「我的餐點」編輯列）

- 品名輸入框打字時，若該店有菜單，下拉顯示品名**包含**輸入文字的品項（比對用上面的正規化），最多 8 筆。
- 每筆顯示：品名、備註（灰）、品項平均（計畫 ② 之後才有；沒有評分顯示 `—`）、價格；自己上次在這家店點過的品項標「上次點」（依 `lastOrder` 的品名＋備註比對）。
- 鍵盤：↑↓ 移動、Enter 帶入、Esc 關閉；滑鼠點選帶入。中文選字中的 Enter（`isComposing` 或 `keyCode 229`）不帶入。
- 帶入：品名、價格、備註一次填好，該列顯示「📋 菜單」標記，游標移到價格欄方便修改。價格沒有、或不是整數（例如每顆 6.5；開團單價格只收整數）就留空。
- 不選、直接打完 → 照打的字存，不連菜單。
- 該店沒有菜單 → 不出現下拉，和現在完全一樣。
- 輸入框空白時不顯示下拉。

### ② 菜單燈箱：品項評分（A 列內展開）

- 「菜單表格」分頁，每列右邊多一欄 `★ 4.7 (3)`，沒有評分顯示 `—`；自己評過的，品名後面標「我 ★4.5」。
- 分類快捷鈕上方加一排「大家推」：每個是小膠囊「品名（備註）★ 4.7」，點了捲到那一列並展開。
- 點任一列 → 在那列下面展開評分面板；再點一次收起；同時只展開一列。
- 面板內容與店家評分相同：選身分（沒選過時）／以 ○○ 身分評分（切換）、半星選擇器、短評（字數/50）、儲存或更新、刪除我的評分（兩段確認）、其他人的評分（新到舊、不含自己）。
- 儲存或刪除後，該列平均、「我」標記、大家推一起更新，面板保持展開。
- 「原始照片」分頁不變。

### ② 開團單：點過的來評分

- 只在 `status === 'closed'` 的卡片（今天已收單＋歷史紀錄），「自己點的」每一列右邊加按鈕：
  - 有 `menuItemId` 且品項還在菜單上，或用品名＋備註對得上目前菜單 → 顯示「☆ 評分」或已評過的「我 ★4.0」。
  - 有 `menuItemId` 但品項已下架 → 仍可評（用點餐列的品名／備註當快照）。
  - 都對不上 → 不顯示按鈕。
- 點按鈕 → 在那列下面展開同一個評分面板（多顯示一行「大家：★ 4.7 · 3 人」）。
- 同一道在燈箱或開團單評，都是同一筆。

### RWD

手機版（≤900px）燈箱與開團單的面板都可完整操作；星星點擊區至少 32px；自動完成下拉不超出畫面寬度。

## 錯誤處理

| 狀況 | 處理 |
|---|---|
| `critieat.itemRatings.v1` 無法使用 | 用示範資料顯示；儲存失敗時在面板顯示「無法儲存到這台電腦的瀏覽器」，保留表單內容 |
| `critieat.itemRatings.v1` 格式壞掉 | 改用示範資料覆寫，在面板顯示「本機品項評分資料無法讀取，已載入示範資料」 |
| 評分的品項已下架 | 燈箱不顯示；開團單連到它的點餐列仍可評 |
| 評分的店家已不在 `data.js` | 忽略 |
| 菜單裡有比對鍵完全相同的品項 | 更新時依順序各自對應；舊紀錄比對時取第一個 |
| 舊菜單資料沒有品項 ID | 讀取時補上固定 ID 並寫回 |
| `critieat.me` 的名字不在成員名單 | 當作還沒選身分 |

## 範圍外

燈箱「點餐模式」（從菜單按＋加入點餐）、品項分數影響店家分數、依品項搜尋店家、品項評分排序／篩選、品項照片、跨店的「我評過的所有品項」頁面、後端與多人同步。

## 驗證

照團隊慣例，不裝測試框架。

- **邏輯**（scratchpad 一次性 node script）：
  - `itemKey` 正規化（空白、全形、大小寫）
  - `assignIds`：同名同備註沿用、漲價沿用、換順序沿用、改名給新 ID、下架、兩個相同比對鍵各對各的、新 ID 不和舊的重複
  - 舊資料補 ID 每次結果相同
  - `ratingKit`：店家評分原本的檢查腳本全數通過；品項評分的唯一鍵、快照欄位驗證
  - `lunch.setItems`：選品項保留 `menuItemId`、改品名清除、改價格保留；`isValidDb` 接受沒有此欄位的舊資料
  - 大家推的門檻、排序、取前 3
- **UI**（headless Chrome）：
  - ① 自動完成：打字出現下拉、鍵盤選取帶入、標記「📋 菜單」、改品名標記消失、沒菜單的店沒有下拉、選字中 Enter 不帶入
  - ② 燈箱：展開評分、儲存後平均／我／大家推更新、重新整理後還在
  - ② 開團單：歷史卡片評一道 → 燈箱看到同一筆；對不上的自由輸入列沒有按鈕
  - 手機 390px 截圖、沒有橫向捲動
