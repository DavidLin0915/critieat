# CRITIEAT 店家評分 設計

日期：2026-10-15　狀態：設計已與使用者確認，待審核 spec；實作計畫下一次再寫

## 目的

讓同事對吃過的店留下星等與一句短評，在美食地圖上一眼看出大家覺得哪家好吃、哪家要小心。
屬於分期表第四期「午餐轉盤及回饋」的「店家星等與短評」（見 `2026-10-08-critieat-phase1-food-map-design.md`）。

## 決定事項（2026-10-15 與使用者確認）

| 項目 | 決定 |
|---|---|
| 評分單位 | 每人每店一筆，可修改（覆蓋舊的）、可刪除。一人多筆／評分歷史之後有需求再調整 |
| 星等級距 | 0.5～5，每 0.5 一級（0.5、1、1.5 … 5），沒有 0 星 |
| 短評 | 選填，一行，最多 50 字 |
| 入口 | 只在美食地圖的店家詳情主動評分；不做開團單收單後提醒 |
| 平均顯示 | 一律顯示平均與人數，例如 `★ 2.0 (1)`；不設最低人數門檻 |
| 具名 | 具名顯示（身分本來就是選名字） |
| 身分 | 共用開團單的 `critieat.me`；地圖頁還沒選過時，在評分區當場選，存回同一個 key |
| 階段 | 原型（純前端、localStorage），後端與多人同步在 DB 階段 |

## 資料

一筆評分：

```
{ storeId: 'R001', member: '小王', stars: 3.5, comment: '辣度很誠實', updatedAt: '2026-10-15T05:30:00.000Z' }
```

- `stars`：0.5～5 之間、0.5 的倍數。不符合就視為壞資料。
- `comment`：字串，存之前去掉前後空白；空字串表示沒寫。最多 50 字（以字元計）。
- `updatedAt`：ISO 字串，每次儲存時更新。
- 唯一鍵：`(storeId, member)`。儲存時如果已經有同一人、同一家店的評分，就直接取代。

儲存格式：localStorage `critieat.ratings.v1` = `{ ratings: Rating[] }`。

未來 DB：`ratings(store_id, member, stars DECIMAL(2,1), comment VARCHAR(50) NULL, updated_at)`，`UNIQUE(store_id, member)`。

### 平均

- 平均 = 該店所有評分的 `stars` 算術平均，四捨五入到小數 1 位，固定顯示 1 位小數（`4.0`，不顯示成 `4`）。
- 沒有評分的店：沒有平均，列表上也不顯示。

## 模組

照現有的原型寫法（IIFE 掛在 `globalThis.CE`、不用打包工具）。

| 檔案 | 內容 |
|---|---|
| `js/rating.js` | 純邏輯，不碰 DOM／localStorage：`isValidRating`、`isValidDb`、`summary(ratings, storeId)` → `{ avg, count }` 或 `null`、`upsert(db, rating)`、`remove(db, storeId, member)`、`normalizeComment`、常數 `MAX_COMMENT = 50` |
| `js/rating-store.js` | 讀寫 `critieat.ratings.v1`：`load()` → `{ db, warning }`、`save(db)`。localStorage 讀不到或格式壞掉時改用示範資料，處理方式照 `lunch-store.js` |
| `js/rating-demo.js` | 示範資料：5～6 家 `data.js` 裡的店，各有幾筆不同成員的評分，有的有短評、有的沒有，星數包含半星 |
| `js/rating-ui.js` | 店家詳情的評分區塊（含半星選擇器），由 `app.js` 的 `renderDetail` 呼叫 |

成員名單沿用開團單的 `members`。在 `lunch-store.js` 加一個只讀的取用函式（類似 `peekCards`）：讀不到時退回示範成員名單，**不會**寫入開團單的示範資料。

第一次載入（沒有 `critieat.ratings.v1`）時寫入示範資料。

## 畫面

### 列表卡片

`item__meta` 那一行最後加上 `★ 4.2 (6)`。沒有評分的店不顯示。

### 店家詳情：評分區塊

放在備註（`detail__note`）之後、按鈕列（`btns`）之前。

```
評分  ★ 4.2 · 6 人
────────────────────
以 小王 身分評分（切換）
☆☆☆☆☆  3.5
[ 短評（選填）            12/50 ]
[儲存]  刪除我的評分
────────────────────
小美  ★ 4.5  辣度很誠實      10/12
阿明  ★ 3.0                 10/09
```

- **標題列**：有評分時顯示 `★ 平均 · N 人`，沒有時顯示「還沒有人評分」。
- **身分**
  - 還沒選身分：顯示「你是誰？」加上成員下拉，選完才出現下面的表單。
  - 已選身分：顯示「以 ○○ 身分評分」和「切換」連結；點「切換」換回下拉。
  - 選擇結果存到 `critieat.me`，和開團單同步。
- **半星選擇器**
  - 5 顆星，點星星的左半邊是 `n − 0.5`、右半邊是 `n`。滑鼠移上去時預覽，旁邊顯示目前的數值。
  - 鍵盤：元件可以 focus，← → 每次調 0.5，範圍 0.5～5。
  - 手機：點按就是左右半邊的判斷，不依賴 hover。
- **短評**：單行輸入框，`maxlength=50`，右側顯示 `字數/50`。
- **按鈕**
  - 還沒評過：「儲存」，沒選星時不能按。
  - 已經評過：表單預先帶入舊的星數和短評，按鈕改成「更新」，旁邊出現「刪除我的評分」。
  - 刪除前不跳瀏覽器對話框，按鈕改成「確定刪除？」，再按一次才刪。
- **其他人的評分**：依 `updatedAt` 新到舊，每行顯示名字、`★ 星數`、短評（沒寫就空著）、`MM/DD`。自己那筆已經在表單裡了，不在列表重複出現。
- 儲存或刪除後，重新繪製詳情和列表，讓平均立刻更新。
- localStorage 存不進去時，在評分區顯示「無法儲存到這台電腦的瀏覽器」，並保留表單內容。

### RWD

手機版（≤900px）的詳情一樣可以完整操作；星星的點擊區至少 32px。

## 錯誤處理

| 狀況 | 處理 |
|---|---|
| localStorage 無法使用 | 用示範資料顯示；儲存失敗時顯示錯誤訊息 |
| `critieat.ratings.v1` 格式壞掉 | 改用示範資料覆寫，並在評分區顯示「本機評分資料無法讀取，已載入示範資料」 |
| 評分對應的店已經不在 `data.js` | 忽略，不顯示 |
| `critieat.me` 的名字不在成員名單裡 | 當作還沒選身分 |

## 範圍外

轉盤依評分調整機率、評分篩選與排序（第五期）、推薦品項（連到結構化菜單）、開團單收單後提醒評分、一人多筆或評分歷史、後端與多人同步、重置評分示範資料的按鈕（需要時手動清掉 localStorage）。

## 驗證

照團隊慣例，不裝測試框架。

- **邏輯**：在 scratchpad 寫一支用完即丟的 node script 測 `rating.js`，範圍包括：
  - 平均的四捨五入和顯示格式
  - 0.5 級距驗證（0、0.3、5.5 不合法）
  - 50 字上限和空白處理
  - 覆蓋同一人的評分、刪除
  - 壞資料的判斷
- **UI**：用 headless Chrome 跑一遍：
  1. 還沒選身分 → 選身分
  2. 評 3.5 星 + 短評 → 列表平均更新
  3. 重新整理後資料還在
  4. 改成 4.5 → 刪除
  5. 用鍵盤 ← → 調整星數
  6. 各截一張桌機（1440px）和手機（390px）的畫面
