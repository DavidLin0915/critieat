# CRITIEAT 午餐轉盤 設計

日期：2026-10-15　狀態：原型已實作（`proto/v1`），待使用者審核

## 目的

不知道中午吃什麼時，從店家裡隨機抽一家，抽到後直接拿去開團單。
一個人自己轉，轉到喜歡的就提議或開單，其他人在開團單上看到結果；不喜歡可以再轉。

## 決定事項（2026-10-15 與使用者確認）

| 項目 | 決定 |
|---|---|
| 使用情境 | 一個人自己轉，不做多人同步 |
| 入口 | 美食地圖篩選列「🎲 不知道吃什麼」；開團單「提議／開單」對話框店家選單旁「🎲」。兩邊共用同一個燈箱 |
| 款式 | 三款可切換：轉盤、彈珠台、競速。記住上次用的款式（瀏覽器本機），第一次預設「競速」 |
| 競速的中獎規則 | 第一個抵達終點的中獎；其他珠子繼續跑完，名次排完為止 |
| 最近吃過 | 預設排除最近 3 天開過團的店，可勾選加回來；天數是設定值 |
| 公平 | 三款每家店中獎機率都相同 |
| 階段 | 第一階段原型（純前端），不需要後端 |

mockup：`.superpowers/brainstorm/79522-1792050831/content/`（`wheel-style.html` 的 A、`wheel-plinko.html`、`wheel-race.html`）。

## 候選店家

1. 起點
   - 從美食地圖開：目前篩選後的店家清單（分類、今天有開等篩選都算）。
   - 從開團單開：今天所有店家。
2. 一律拿掉今天確定公休的店（`status === 'closed'`）。營業時間沒填（`unknown`）的照樣放進來。
3. 「排除最近吃過」勾選時（預設勾），再拿掉**今天以前**最近 N 天有午餐卡的店。
   - N 為設定「轉盤排除天數」，預設 3；0 表示不排除。「最近 N 天」指今天往前數 N 個日曆天（N=3 時，今天是 10/15 就看 10/12～10/14）。
   - 算的是開團單資料裡的卡片（`critieat.lunch.v1`），只算真的開過單的（點餐中或已收單）；停在提議中、沒人開單的不算。取消的團本來就不留卡片。
   - 今天的卡片不算，抽到今天已經有人開的店，剛好可以去跟。
   - 燈箱上方列出被排除的店與日期，例如「已排除：丸亀製麵（昨天）、八方雲集（3 天前）」。同一家多天都有，寫最近一次。
4. 剩下不到 2 家：不能開始，提示「候選不到 2 家，放寬篩選或把最近吃過的加回來」。

### 數量上限

| 款式 | 一次最多 | 超過時 |
|---|---|---|
| 轉盤 | 12 | 每一輪從候選隨機挑 12 家上場 |
| 彈珠台 | 電腦 10、手機（≤900px）6 | 同上 |
| 競速 | 30 | 同上 |

有隨機挑時，上方寫「共 23 家候選，這輪隨機挑 12 家」。每次「再來一次」都重新挑。
隨機挑一批再從中抽一家，每家店最後被抽中的機率仍然都是 1/總數。

## 三款

### 轉盤

圓形轉盤，格子交錯用淺青、淺紫，指針在正上方。先公平抽出一家，算好讓那一格停在指針下的角度，轉 5 圈以上減速停下，約 3.6 秒。店名太長只顯示前 6 個字加「…」。

### 彈珠台

深色板子、交錯的釘子，底下每一格一家店，店名直書寫在格子下方。先公平抽出一家，再用同一套物理模擬試不同的投入位置與亂數，找到會落進那格的路徑後照著播（試 3000 次找不到就用最後一次的結果，畫面與結果一致）。撞到的釘子亮一下，約 3 秒。

### 競速

用 matter.js 物理引擎。每家店一顆珠子，標店名前兩個字，顏色依分類。全部放在起跑閘門後，**起跑位置隨機分配**，按「開跑！」打開閘門。畫面跟著最前面的珠子往下捲，右側細條顯示每顆珠子的進度，旁邊是即時名次。

**地圖**（2026-10-15 與使用者一起調整定案，資料在 `js/pick-race-maps.js`）：板子上方「地圖：🎲 隨機 ▾」，預設每場隨機，選了某張後「再來一次」沿用。

| 地圖 | 主要機關 |
|---|---|
| 霓虹彈珠台 | 彈跳墊陣列、之字坡、翹翹板、十字風車、滑動擋板 |
| 機關工廠 | 三道定時活門（珠子在上面集合再放行）、十字風車、滑動擋板 |
| 分岔迷宮 | 兩次分岔（2 條、3 條路）、兩個窄口、翹翹板 |

機關：釘子區、之字坡、漏斗、彈跳墊（會閃）、翹翹板（被珠子壓了會轉、沒東西時回正）、十字風車（一直轉）、滑動擋板（約 4 秒來回）、活門（要關時若有珠子在門內就延後關）。牆邊每 70px 自動補小擋板（附近 34px 內已有機關就不放），避免貼牆直落。

**節奏**：重力 1.0、空氣阻力 0.012、每物理步速度上限 5px（一格算兩步），第一名約 25～32 秒。珠子 2 秒以上幾乎沒動就往旁邊上方推一下；每步把珠子限制在左右牆內（被彈飛也不會出界）。60 秒還沒人到就由最前面那顆中獎，75 秒停止。

設計原則（調圖時遵守）：機關之間空檔約 100px 內；貼牆的圓形障礙圓心離牆 10px 內（珠子才不會被夾住）；機關之間至少留 40px（不夾出口袋）；翹翹板外端離牆約 30px，上方牆邊固定放擋板。

公平性：起跑位置是隨機分配給店家的，不管跑道怎麼設計，每家店拿第一的機率都一樣。

## 抽到之後

| 從哪裡開 | 按鈕 |
|---|---|
| 美食地圖 | 「用這家開單」「用這家提議」「在地圖上看這家」「再來一次」 |
| 開團單對話框 | 「就這家」「再來一次」 |

- 「用這家開單／提議」：前往 `lunch.html?new=<店家ID>&as=open`（提議為 `as=propose`），進頁面後打開「提議／開單」對話框並選好店家，`as` 對應的按鈕（「直接開單」或「先提議」）預先聚焦，由使用者確認後按下。網址帶的店家 ID 不存在就照常打開頁面、不開對話框；`as` 缺少或不認得時聚焦「直接開單」。開完網址參數從網址列移除，重新整理不會再開一次。還沒選身分時先選身分，再開對話框。
- 「在地圖上看這家」：關掉燈箱，在地圖選中那家店（跟點清單一樣）。
- 「就這家」：關掉燈箱，把店家帶進對話框的下拉選單。
- 轉的過程中可以關掉燈箱，關掉就當沒轉過。

## 畫面

- 燈箱沿用菜單燈箱的樣式（`.mdlg`）。上方三個分頁「轉盤／彈珠台／競速」，下面是排除說明列＋「排除最近吃過」勾選框，再來是板子、開始按鈕、結果區。
- 開始按鈕文字：轉盤「轉！」、彈珠台「投！」、競速「開跑！」；轉的時候按鈕停用。
- 換分頁會停掉正在跑的動畫，換成新款式（候選不變）。
- 手機（≤900px）燈箱全螢幕，板子寬度跟著螢幕縮放。
- 系統設定「減少動態效果」（`prefers-reduced-motion`）時不播動畫，直接顯示結果。

## 檔案

| 檔案 | 內容 |
|---|---|
| `proto/v1/js/pick.js` | 純邏輯：`candidates(stores, cards, { today, days, includeRecent })` → `{ list, excluded }`；`sample(list, max, rnd)`；`pickIndex(n, rnd)`。不碰 DOM |
| `proto/v1/js/pick-wheel.js` | 轉盤 |
| `proto/v1/js/pick-plinko.js` | 彈珠台（模擬與找路徑放在可單獨驗證的函式） |
| `proto/v1/js/pick-race.js` | 競速（照地圖資料蓋跑道） |
| `proto/v1/js/pick-race-maps.js` | 競速的三張地圖資料 |
| `proto/v1/js/pick-lightbox.js` | 燈箱：分頁、排除說明與勾選、結果按鈕、記住款式（`localStorage` `critieat.picker.mode`）。對外 `CE.openPicker({ stores, source: 'map' \| 'lunch', onPick })` |
| `proto/v1/js/data.js` | 設定加一列「轉盤排除天數,3」 |
| `proto/v1/js/stores.js` | `rowsToSettings` 讀「轉盤排除天數」，格式錯誤用預設 3 |
| `proto/v1/index.html`、`js/app.js` | 「🎲 不知道吃什麼」按鈕；載入 `lunch.js`、`lunch-store.js` 以讀最近的午餐卡 |
| `proto/v1/js/lunch-store.js` | 新增 `peekCards()`：只讀不寫，讀不到或格式不對回傳 `[]`，不會寫入示範資料 |
| `proto/v1/lunch.html`、`js/lunch-app.js` | 對話框「🎲」；支援 `?new=<店家ID>&as=open\|propose` |
| `proto/v1/css/style.css` | 燈箱、三款板子、結果區 |

三款共用介面：`CE.pickers.<款式>.mount(容器, 店家清單, { onWin, small })` 回傳 `{ start(), destroy() }`。

matter.js 從 `https://cdnjs.cloudflare.com/ajax/libs/matter-js/0.19.0/matter.min.js` 載入（固定版本）。載入失敗時「競速」分頁顯示「競速需要網路載入物理引擎，請改用其他款式」。

## 出錯處理

| 狀況 | 處理 |
|---|---|
| 候選不到 2 家 | 開始按鈕停用，顯示提示 |
| matter.js 載入失敗 | 競速分頁顯示提示，其他兩款照常 |
| 開團單資料讀不到 | 當作沒有最近吃過的店，不排除 |
| `?new=` 店家不存在 | 照常開頁，不開對話框 |

## 驗證

- `pick.js` 以 scratchpad 的一次性 node 腳本驗證：公休排除、unknown 保留、最近 N 天的邊界（第 N 天算、第 N+1 天不算、今天不算）、只有提議的卡片不算、勾選加回來、N=0、排除說明取最近一次、不到 2 家、`sample` 超過上限時數量與不重複、大量抽樣分布大致平均。
- 彈珠台找路徑：每一格都找得到、平均耗時。
- 畫面以 headless Chrome 操作與截圖（390、1440 寬）：三款各跑一次並出結果、換分頁、從地圖與開團單兩個入口、「用這家開單」跳轉並選好店家、「就這家」帶入、0 個例外、沒有橫向捲動。
