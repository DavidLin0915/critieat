# CRITIEAT 開團單（午餐卡）原型 設計

日期：2026-10-14　狀態：原型已實作（`proto/v1/lunch.html`），待審核

## 目的

每天中午要有人揪團、收大家要點什麼、再整理給店家。開團單把這件事放在網頁上：
有人丟出想吃的店，大家 +1；決定之後開單，各自填餐點；收單後自動整理出訂餐彙總，給負責訂餐的人打電話或貼到外送平台。

這一版是**純前端原型**，用假資料、資料存在瀏覽器，用來讓團隊試流程與畫面；確認後才做 API / DB。

## 決定事項（2026-10-13～14 與使用者確認）

| 項目 | 決定 |
|---|---|
| 頁面 | 獨立的「開團單」頁，從導覽列進入；三欄版面（視覺見 `.superpowers/brainstorm/32113-1791890674/content/lunch-card-states.html`） |
| 狀態 | 提議中（紫）→ 點餐中（青）→ 已收單（灰）；可跳過提議直接開單 |
| 點餐輸入 | 一列一項（品項、價格、備註），收單時同名品項可合併 |
| 價格 | 選填；有填才算小計與合計 |
| 付款 | 只記錄「付錢者」（誰先付給店家），預設開單者；不追蹤誰付給付錢者 |
| 收單後修改 | 不鎖單，每人仍可改自己的列；收單後改過的列加標記提醒 |
| 原型資料 | 可實際操作，存在 localStorage；切換身分扮演不同人；可重置示範資料 |

## 資料

### 午餐卡（card）

| 欄位 | 說明 |
|---|---|
| `id` | 卡片 ID |
| `date` | 日期（台灣時間 `YYYY-MM-DD`） |
| `storeId` | 店家 ID（對應美食地圖店家，如 `R006`） |
| `storeName` | 建立時的店名（店家資料找不到時顯示用） |
| `status` | `proposed` 提議中／`ordering` 點餐中／`closed` 已收單 |
| `proposer` | 提議者（直接開單時與開單者相同） |
| `owner` | 開單者；提議中為空，按「開始點餐」的人成為開單者 |
| `note` | 一句備註，選填 |
| `voters` | +1 的成員名單（提議者自動在內） |
| `closeAt` | 收單時間 `HH:MM`，預設取設定的訂餐時段結束（13:30） |
| `pickupAt` | 取餐時間 `HH:MM`，預設取設定的取餐時間（14:00） |
| `payer` | 付錢者，預設開單者 |
| `createdAt`、`closedAt` | 建立、收單時間（ISO 字串） |
| `changedAfterClose` | 收單後是否有人新增、修改或刪除點餐列 |
| `items` | 點餐列（見下表） |

### 點餐列（item）

| 欄位 | 說明 |
|---|---|
| `id` | 列 ID |
| `member` | 誰點的 |
| `name` | 品項名稱，必填 |
| `price` | 0 以上整數，可為空（`null`） |
| `note` | 備註，選填 |
| `updatedAt` | 最後修改時間 |
| `afterClose` | 是否在收單後新增或修改 |

### 成員（member）

名稱字串清單。身分存在瀏覽器（`localStorage`），可切換、可新增名字。

以上格式之後對應資料庫的 `cards`、`votes`、`order_items`、`members` 表。

## 狀態與操作

| 操作 | 誰可以 | 條件 | 結果 |
|---|---|---|---|
| 建立卡片「先提議」 | 任何人 | — | 提議中，`proposer` = 自己，`voters` = [自己] |
| 建立卡片「直接開單」 | 任何人 | — | 點餐中，`proposer` = `owner` = `payer` = 自己 |
| ＋1／取消 ＋1 | 任何人 | 提議中 | 加入或移出 `voters`（提議者不能取消自己） |
| 開始點餐 | 提議者或 `voters` 中的人 | 提議中 | 點餐中，`owner` = `payer` = 自己 |
| 新增／修改／刪除點餐列 | 只能改自己的列 | 點餐中或已收單 | 已收單時新增或修改的列 `afterClose` = true |
| 延後收單 | 開單者 | 點餐中 | `closeAt` + 10 分鐘 |
| 現在收單 | 開單者 | 點餐中 | 已收單，記錄 `closedAt` |
| 改付錢者 | 任何人 | 已收單 | 從成員名單選 |
| 取消這團 | 開單者（提議中為提議者） | 提議中或點餐中 | 確認後刪除卡片 |

- 過了收單時間**不會**自動收單，只顯示「已超過收單時間」。
- 頁面只顯示**今天**的卡片；之前的卡片不出現，沒成團的提議因此自然消失。
- 已收單時刪除自己的列：直接刪除，彙總頂端的「收單後有修改」提示照樣出現（記在卡片上的 `changedAfterClose` = true）。

## 計算

- **每人小計**：該人有填價格的列加總；全部沒填價格則不顯示金額。
- **合計**：所有已填價格的列加總。全部有價格時顯示「N 人 $總額」；部分沒填時顯示「已知 $xxx（M 項未填價格）」。
- **訂餐彙總**：品項名稱與備註都相同（去頭尾空白後比對）的列合併成一筆「×份數」；價格取那幾列已填價格的總和；依第一次出現的順序排列。
- **複製彙總文字**：純文字格式，例如：

  ```
  八方雲集 10/14 取餐 14:00
  招牌鍋貼 10 顆 ×3
  酸辣湯 ×2
  韭菜水餃 10 顆（不要辣）×1
  共 6 項　$355
  ```

  有未填價格時最後一行改為「共 N 項　已知 $xxx」。

## 畫面

沿用美食地圖的頁首、風格與三欄版面。三個頁面導覽列的「開團單」都改為可點，連到 `lunch.html`。

### 頁首右側

- 今天日期。
- 身分 pill「👤 小明 ▾」：點開選成員或新增名字。
- 還沒選身分時，進頁面先跳出選人視窗。

### 左欄：今天的卡片

- 每張卡片：店名、「某某 開單 · 13:30 收單」或「某某 提議」、狀態徽章與人數／+1 數。
- 排序：點餐中 → 提議中 → 已收單，同狀態依建立時間。
- 最下方「＋ 提議／開單」按鈕；最底下小字「重置示範資料」。
- 預設選中第一張卡片；沒有卡片時中欄顯示「今天還沒有人開團」與建立按鈕。

### 中欄：選中的卡片

- **提議中**：備註、想吃的人、「＋1 我也想吃」（已 +1 時為「取消 +1」）、有權限時顯示「開始點餐 →」。
- **點餐中**：
  - 收單時間、剩餘分鐘（收單那一分鐘顯示「收單時間到了」，過了顯示「已超過收單時間」）、取餐時間。
  - 每人的點餐列（品項、備註、價格）。
  - 「我的餐點」編輯區：一列一項，品項／價格／備註，「＋ 再加一項」、刪列、送出。
  - 打了但還沒送出就切到別張卡或換身分，內容會留著，切回來還在；左欄那張卡片顯示「✎ 餐點還沒送出」。只存在記憶體，重新整理就沒了。
  - 「還沒點」：`voters` 中還沒有點餐列的人。
  - 開單者另外看到「延後收單」（+10 分鐘）、「現在收單」、「取消這團」。
- **已收單**：
  - 每人品項（一行一項，2026-10-15 確認維持）、備註、小計；最後一行合計。
  - 「付錢者：某某 ▾」。
  - 「我的餐點」仍可編輯；`afterClose` 的列帶「收單後修改」標記。

### 右欄

- **提議中、點餐中**：店家資訊（分類、今天營業時間、電話）、「📋 看菜單」按鈕（2026-10-15 取代原本的菜單照片區，見 `2026-10-15-critieat-menu-design.md`）、「在美食地圖上看這家 →」。
- **已收單**：訂餐彙總（合併後品項、份數、價格、合計）、「收單後有修改」提示（有的話）、「複製彙總文字」、店家電話。

### 建立卡片視窗

- 店家下拉選單：今天有營業的排前面，沒營業的標「今天公休」。
- 備註（選填）。
- 「先提議」「直接開單」兩個按鈕。

## 出錯處理

| 情況 | 處理 |
|---|---|
| localStorage 讀不到或格式壞掉 | 改用示範資料，頁面上方提示一行「本機資料無法讀取，已載入示範資料」 |
| 卡片的店家找不到 | 顯示 `storeName`，右欄顯示「找不到店家資料」 |
| 品項沒填 | 不能送出，該列標示錯誤 |
| 價格不是 0 以上整數 | 不能送出，該列標示錯誤；空白可以 |
| 複製失敗（瀏覽器不允許） | 顯示彙總文字框讓使用者自己選取複製 |

## 歷史紀錄與「我上次點什麼」（2026-10-15 追加）

- 左欄上方日期切換「‹ 10/15（四）今天 ›」，只在有午餐卡的日子與今天之間跳。
- 過去的卡片唯讀：不能 +1、點餐、收單、改付錢者、取消；上方顯示「📅 這是 10/14（三）的紀錄，只能查看」，左欄底部改成「← 回到今天」。
- 頁面上方提示列：一般提示（已送出、操作失敗）切換卡片、日期或身分時清掉；存檔或讀檔的問題會一直顯示，按「知道了」或之後存檔成功才消失。
- 「我的餐點」編輯區：如果我在同一家店、今天以前點過，顯示「上次 10/12（一）你點了：…」與「帶入」，按了把上次的品項加進編輯列。
- 示範資料多了前幾天的 4 張已收單卡片（含小明在八方雲集的紀錄）。
- 第二階段資料進 DB 後，紀錄由大家共用；這版只在自己的瀏覽器。

## 驗證

照團隊慣例，不裝測試框架：

- `lunch.js` 以 scratchpad 的一次性 node 腳本驗證：各狀態轉換與不合法轉換、權限、`afterClose` 標記、小計、彙總合併（同名不同備註不合併）、部分價格的合計與複製文字。
- 畫面以 headless Chrome 截圖檢查：三種狀態、切換身分後的按鈕差異、建立卡片視窗、重置示範資料。預覽網址 `http://localhost:8000/lunch.html`。

## 這一版不做

後端與多人同步、店家新增／編輯、菜單上傳與辨識（見 `2026-10-15-critieat-menu-design.md`）、飲料團、轉盤與評分、自動收單、通知。

## 不顯示收單／取餐時間（2026-10-21 使用者決定）

午餐時間不固定，開團單上所有時間都拿掉：卡片標題下方與左欄只顯示「某某 開單」、不顯示收單倒數；拿掉「延後收單」按鈕（收單仍由開單者手動按「現在收單」）；訂餐彙總只顯示付錢者；複製文字第一行只有「店名 月/日」。資料欄位 `closeAt`、`pickupAt` 保留但不顯示。
